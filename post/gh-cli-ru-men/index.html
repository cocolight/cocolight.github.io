GitHub CLI（gh）常用命令清单

2026-09-30 • 3 分钟阅读 • git • github · git

前提：进入本地git仓库目录执行，会自动识别当前仓库；不在仓库可以加 -R 用户名/仓库名 指定仓库

一、账号认证相关（你正在用的）

gh --version                 # 查看版本，验证安装
gh auth login                # 登录（就是刚才执行的）
gh auth status               # 查看当前登录状态，验证token是否正常
gh auth logout               # 本地退出登录（不会网页撤销授权）
gh api /user                 # 联网测试，调用github api，输出你的账号信息
gh browse                    # 在浏览器打开当前仓库主页

二、仓库 repo 操作

gh repo clone 用户名/仓库名    # 克隆仓库（等价git clone，自动用你配置的ssh）
gh repo create               # 新建github远程仓库（本地目录一键推送到github）
gh repo view                 # 查看仓库信息，加 --web 直接浏览器打开仓库
gh repo list 你的用户名       # 列出你所有仓库

三、Pull Request PR（gh最核心功能，不用切网页）

gh pr status                 # 查看当前仓库PR状态（你创建的、需要你review的）
gh pr list                   # 列出所有open的PR
gh pr checkout 123           # 把编号123的PR，拉到本地新建分支，直接看代码
gh pr create                 # 基于当前分支，创建PR（交互式，填标题描述）
gh pr view 123               # 查看PR详情，--web 浏览器打开PR页面
gh pr diff 123               # 在终端看PR代码改动
gh pr review 123             # 给PR做评审（approve/comment/request changes）
gh pr merge 123              # 合并PR（支持squash/rebase/merge三种方式）
gh pr close 123              # 关闭PR

四、Issue 任务单

gh issue list                # 列出open的issue
gh issue create              # 新建issue
gh issue view 5              # 查看5号issue
gh issue comment 5           # 给5号issue留言
gh issue close 5             # 关闭issue

五、Actions CI流水线

gh run list                  # 列出最近的CI执行记录
gh run watch 12345           # 实时看某次流水线日志
gh run download 12345        # 下载流水线产出的artifacts制品
gh workflow list             # 列出仓库所有workflow

六、Release、Gist、搜索

gh release create v1.0.0     # 新建版本发布
gh gist create file.txt      # 创建gist代码片段
gh search prs "is:open"      # 全局搜索PR
gh search issues "bug"       # 全局搜索issue

七、小技巧

  1. 查看帮助：gh 子命令 -h，例如 gh pr -h、gh pr create -h
  2. 全局参数 -R owner/repo：不在仓库目录，指定仓库操作
gh pr list -R cli/cli
  1. 一键打开网页：大部分命令加 --web，直接跳转github网页，比如 gh pr view --web

典型开发工作流（日常最常用一套）

# 1. 切新分支、改代码、git add + git commit + git push
# 2. 执行下面，交互式创建PR
gh pr create
# 3. 查看CI检查是否通过
gh pr checks
# 4. 评审完成后合并
gh pr merge

补充

你配置的是SSH协议，gh只负责API鉴权（token），git拉取推送代码走你本地RSA密钥，两者互不干扰。

所有gh pr/issue操作都依赖登录的token权限，登录成功后才能执行。

入门实操顺序建议

登录成功后，先执行

gh auth status
gh browse

验证连通，再尝试 gh pr status 熟悉PR操作。
