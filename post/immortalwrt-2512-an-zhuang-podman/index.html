immortalwrt 25.12 安装 Podman

2026-10-03

本文提供了在 ImmortalWrt LuCI 界面配置 IPTV-API 容器的详细步骤，涵盖镜像选择、网络设置、持久化存储、端口映射、环境变量配置等关键点，并提醒架构兼容性、存储路径调整等注意事项，帮助用户顺利部署并优化资源占用，实现高效直播源生成。

根据你提供的截图和 IPTV-API 的官方文档，下面是一份在 ImmortalWrt 的 LuCI 界面中配置该容器的完整参考。

:clipboard: 核心配置速览

在填写表单前，可以先了解几个关键点：镜像使用 guovern/iptv-api:latest；网络建议选择 bridge (default)；持久化需要将配置和输出目录挂载到 /overlay 下；端口将容器内的 8080 映射到路由器上未被占用的端口，例如 8125。

:computer: 界面配置详解

以下按截图中的字段顺序逐一说明：

基础信息

    • 容器名称：建议填写 iptv-api，方便识别。
    • 固件文件：填写 docker.io/guovern/iptv-api:latest。注意不要填写旧版的 tv-driver 或 tv-requests，那些是已废弃的镜像名。
    • Pod：保持 （无）。
    • 命令：留空。镜像有默认的启动命令，不需要覆盖。
    • 端口映射：
    • 8080:8080 是核心。如果路由器上 8080 已被占用，可以将宿主机端口改为其他空闲端口，例如 8125:8080。
    • 8443:443 可以暂时不填，除非你需要 HTTPS 访问。
    • 暴露端口：可以留空podman 的端口映射通过上面的“端口映射”字段即可完成，这个字段通常用于文档说明。

存储配置

  • 卷：需要手动进ssh先创建。需要挂载两个目录：
  • /overlay/podman/volumes/iptv-api/config:/iptv-api/config：用于保存频道模板、配置文件等。
  • /overlay/podman/volumes/iptv-api/output:/iptv-api/output：用于保存生成的直播源结果文件。
  • 注意：路径请根据你之前设置的实际 graphroot 进行调整。如果你把 graphroot 设在了 USB 存储上，这里也要相应修改。

网络与运行策略

  • 网络：选择 bridge (default)。这是最稳妥的选择，容器通过 NAT 共享路由器 IP，无需额外配置 macvlan。
  • 重启策略：建议选择 失败时，也可以根据需求选择 总是，确保路由器重启后容器能自动运行。

环境变量与资源限制

  • 环境变量：可以留空，或者根据需要填写：
    • PUBLIC_DOMAIN：设置为路由器的局域网 IP，例如 192.168.1.1。这会影响生成结果中的地址。
    • PUBLIC_PORT：设置为你在“端口映射”中使用的宿主机端口，例如 8125。
  • CPU / 内存限制：强烈建议设置。IPTV-API 在测速时可能占用较高资源。考虑到路由器性能，可以设置为 CPU 限制 1.0，内存限制 512m 或 1g。

:gear: 关于其他字段

  • 工作目录：通常保持默认 /app 即可。
  • 主机名、用户、附加组、标签：这些通常不需要填写。
  • 特权模式、分配 TTY、自动删除：保持不勾选。

:warning: 重要注意事项

  1. 架构兼容性：IPTV-API 官方支持 amd64arm64 和 arm v7 架构。在拉取镜像前，请确认你的路由器 CPU 架构是否在此范围内（可通过 SSH 执行 uname -m 查看）。如果你的路由器是 mips 架构，将无法运行此镜像。
  2. 镜像拉取：在 LuCI 的 Podman → 镜像 页面拉取 guovern/iptv-api:latest。如果拉取缓慢，可以尝试配置 Docker 镜像加速器，或参考官方文档中提供的代理加速地址。
  3. 持久化存储：请务必确认你的 graphroot 已从默认的 /var/lib/containers/storage（位于内存）修改到 /overlay 或 USB 存储上，否则上述卷挂载也可能在重启后丢失。
  4. 端口占用：在填写端口映射前，可以用 netstat -tlnp 或 ss -tlnp 检查宿主机端口是否已被占用。
  5. 首次启动与配置：容器首次启动后，你需要按照官方教程，在 config 目录下创建 user_demo.txt 模板和 user_config.ini 配置文件。这些文件会保存在你挂载的 /overlay/podman/volumes/iptv-api/config 目录中，你可以通过 SSH 或 LuCI 的文件管理器进行编辑。

:wrench: 故障排查

如果容器启动失败，可以在 LuCI 的 Podman → 容器 页面查看容器日志，或通过 SSH 执行 podman logs iptv-api 查看详细输出。
