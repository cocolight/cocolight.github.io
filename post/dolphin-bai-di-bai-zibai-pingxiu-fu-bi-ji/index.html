Dolphin 白底白字（白屏）修复笔记

2026-10-17

背景：在主账户 aliha 装完 KOS 后，深色模式下 Dolphin 出现「背景白 + 文字白」——几乎不可读。这是 KOS 与 KDE 原生外观系统耦合出的真实坑，记下根因与已验证可走的修复步骤。

根因（两套外观系统不同步）

  1. KDE 全局配色方案（~/.config/kdeglobals 的 ColorScheme）被推成了 BreezeLight（浅色）——浅色方案的视图背景是白色。
  2. KOS Glass 主题是恒定暗色玻璃（glassFollowsAppearanceMode=false，强制常量暗色）。它让外壳（顶栏/Dock/启动器）看起来是深色，但不修改 KDE 全局配色方案 key。
  3. 于是出现割裂：KOS 外壳是暗色玻璃，而 Dolphin 这类原生 KDE 应用仍按浅色方案去渲染自己的视图内部 → 白底；同时 KOS 的暗色又让某些前景（文字/图标）按暗色取色 → 白字。结果就是白底白字。
  4. 残留放大器：~/.config/dolphinrc 里还留着 ColorScheme=BreezeClassic 的按应用覆盖（[UiSettings] 段），加上 Dolphin 内存中已加载的 palette 残留，使错乱被固化。

本质：KOS 改了外观「表层」（暗色玻璃 + 可能把全局 scheme 搞成 light），但没正确统一 Dolphin 这类原生应用的内部配色。这不是 Dolphin 的 bug，是 KOS 外观接管不彻底。

已验证可走的修复步骤

  • ① 把 KDE 全局配色切回暗色（让 Dolphin 重新读暗色方案）： 
    plasma-apply-colorscheme BreezeDark      # 本机正常终端直接跑即可

    该命令会同时写 kdeglobals 并通知运行中的 Plasma，立即生效。

  • ② 清除 Dolphin 的按应用配色覆盖残留：编辑 ~/.config/dolphinrc，删掉 [UiSettings] 段里的 ColorScheme=BreezeClassic（若该段只剩这一行就整段删掉）。
  • ③ 修正文件属主/权限（若曾被 root 写过，属主变成 root 会导致下次登录 Dolphin 读不到）： 
    sudo chown 用户名:用户名 ~/.config/dolphinrc ~/.config/kdeglobals
chmod 644 ~/.config/dolphinrc ~/.config/kdeglobals
  • ④ 重启 Dolphin 让内存里残留的白 palette 失效： 
    dolphin --quit        # 或手动关掉所有 Dolphin 窗口再重开
  • ⑤ 验证：重开 Dolphin，背景应为暗色、文字浅色、可读。

防复发

  • KOS 下次登录可能再把全局 scheme 推回 light。两种对策二选一：
    • 在 KOS 设置 → 显示 → 色彩模式 → 选「深色」；
    • 或登录后手动 plasma-apply-colorscheme BreezeDark。
  • 若希望 Dolphin 永远暗色、不受 KOS 切换影响：保持第 ② 步删掉的按应用覆盖，且不要在 Dolphin 设置里手动锁定某个配色（锁定会产生新的 ColorScheme= 覆盖，反而回到错乱）。
